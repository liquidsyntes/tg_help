# Git Workflow

Правила обязательны для агента при работе с этим репозиторием. Если агент видит, что накопились незакоммиченные изменения (`git status` не пустой) дольше одной логической правки — он должен сам предложить коммит, не дожидаясь просьбы.

## Начало новой задачи

```bash
git checkout main
git pull
git checkout -b feat/название-задачи
```

## Во время работы

Коммитить небольшими кусками, не копить изменения. Правило: закончил один осмысленный шаг (функция, фикс, файл) — сразу коммит, не откладывай "на потом".

```bash
git add .
git commit -m "краткое и понятное описание изменений на русском"
```

Триггеры для коммита (агент должен напоминать сам):
- Прошло больше 20-30 минут работы без коммита
- Файл или модуль дописан и рабочий
- Перед переключением на другую подзадачу
- Перед запуском тестов или сборки

## Перед merge в main

Подтянуть свежий main в свою ветку:

```bash
git checkout main
git pull
git checkout feat/название-задачи
git merge main
# Решить конфликты если есть
# Протестировать что всё работает
```

## Влить в main

```bash
git checkout main
git merge --no-ff feat/название-задачи
git push
```

## Убрать использованную ветку

```bash
git branch -d feat/название-задачи
```

## Проверить историю

```bash
git log --graph --all --decorate --oneline --date-order
```

## Naming веток

| Префикс | Назначение |
|---------|-----------|
| `feat/` | Новый функционал |
| `fix/` | Баги |
| `refactor/` | Переработка кода |
| `chore/` | Зависимости, Prisma, конфиги |

## Правила

- Одна задача = одна ветка
- Ветка влита = ветку удалить
- Следующая задача = новая ветка от свежего main
- Никогда не коммитить напрямую в main
- `merge` для интеграции, `rebase` только для локальной уборки
- Не копить изменения без коммитов, коммит - это чекпоинт, а не финальный отчёт

## Для агента (Antigravity)

- Перед завершением любой задачи проверяй `git status` и `git diff` - если есть незакоммиченные изменения, спроси пользователя или закоммить сам с осмысленным сообщением
- Не переходи к следующей подзадаче с незакоммиченными изменениями предыдущей
- Если правки затрагивают несколько логических блоков - предлагай разбить на несколько коммитов, а не один большой
